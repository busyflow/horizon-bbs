# Architecture & Horizon Mixins Integration

`horizon-bbs` separates the pure-Rust **BBS 1.20.1 Cinematic Engine** (`src/lib.rs`) from the **Horizon Native Adapter** (`native/horizon.rs`).

## Module Layout

1. **`src/lib.rs` (Standalone BBS 1.20.1 Core Engine):**
   - Pure Rust library with zero game-engine coupling.
   - Implements `Film`, `Replay`, `ReplayGroup`, `GroupClipboard`, `KeyframeChannel`, `Keyframe`, `Interpolation`, `Form`, `Pose`, `BodyPart`, `Transform`, `CameraClip`, `Config`, and `Runtime`.
   - Defines the `Host` trait (`player`, `apply_camera`, `apply_replays`) so the engine can be unit-tested in-memory (`tests/bbs_engine.rs`) and embedded directly inside `horizon-client`.
2. **`native/horizon.rs` (Horizon Host Adapter):**
   - Implements `Host` for Horizon's `Game<'_>`.
   - Provides thread-local per-world state (`STATES`) and `/bbs` command dispatching (`bbs_command`).
3. **`mixins/bbs/` (`horizon-mixins` 0.6.0 Bundle):**
   - `horizon-mixin.toml`: Declares the `bbs` module injection into `crates/horizon-client/src/game.rs` and cancellable `HEAD` hooks on `run_command` and `guest_command`.
   - `runtime.rs`: Generated by `python3 tools/bundle.py` by combining `native/horizon.rs`, `src/lib.rs`, and `tests/bbs_engine.rs` into a single self-contained Rust module with no external `include!` or `mod` files, as required by `horizon-mixins`.
